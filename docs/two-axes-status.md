## 当前判断

已实现有预算、工具调用及确定性引用校验的LangGraph单Agent原型。真实资料目前只能待审核预览，还未形成完整的患者咨询闭环。现有问题主要是资料接入、审核流程、症状咨询状态和验收集，尚无测量证据说明需要多Agent。

本次读取源码及本地资料清单核实：真实检索13单元（高血压PDF章节9个、疾控网页4篇），允许生成的已审核真实单元0个。后续下载的呼吸道补充原件5份尚未索引。两份开发问题集各20题，都是合成用例，不能等同于40题已通过的医学验收。

## 第一板斧：材料与外部能力

| 什么通过RAG召回 | BM25检索，保留来源、日期、原文、审核状态；PDF有页码，HTML用正文定位 | 清理新5份资料；按问答/章节切分且保留限制条件；标记主题/人群/版本；核对定位和表格；建立审核发布流程 |
| 什么做Tool Calling | `search_evidence`、`get_evidence`、`ask_user`；真模型完整往返已有验证记录 | 扩展追问字段与校验；定义空结果、暂时失败、不可重试错误的稳定行为；暂无理由增加诊断/剂量工具 |
| 什么用MCP | 已提供统一资料查询和读取入口 | 保持与HTTP共用证据服务；遗留工具仍需明确用途；有真实跨客户端需求后再增加接入系统 |
| 什么走CLI | 资料下载、PDF处理、测试及开发操作 | 将下载→校验→抽取→切块→待审输出整理成可复现命令，查询阶段不运行Shell |
| 哪些动作需权限和审计 | Agent暴露的3个工具没有写库或任意路径读取能力；运行有轨迹 | 当前网页导入和历史查询没有用户鉴权、角色隔离；审核发布需要授权与记录；本机原型不能等同于可向真实用户部署的服务 |

材料处理与审核应分开：程序能校验格式、引用和完整性，不能自行授予医学审核通过。新增HTML目前固定pending，尚无正式发布入口。不要为让页面显示答案而直接批量改approved。

## 第二板斧：单Agent编排

| 模块 | 当前已有 | 还要做 |
| --- | --- | --- |
| Prompt | 独立SYSTEM指令、工具约束、JSON输出协议、未审/冲突/失败处理要求 | 按患者科普、症状咨询、用药资料阅读定义不同任务协议，不能只扩大同一个Prompt |
| Agent Loop | LangGraph模型→工具→模型→校验；调用预算、时间上限、一次引用修复、暂时工具错误重试和重复调用阻断 | 让追问进入可恢复的等待状态；验证超时、失败与用户补充后的继续执行；需要时再实现进程级故障恢复 |
| Memory | 本次运行状态；SQLite保存运行记录；前端提交两项known_context | 增加session_id与结构化会话状态，用户补充后恢复同一次任务；新会话隔离；“不清楚”保留为未知，不视作正常。当前没有checkpointer/thread_id持久会话恢复，运行历史不等于Memory |
| Skill | 有宿主代码中的统一约束，没有项目级业务Skill模块 | 提取可复用任务流程，例如“症状信息收集→检查关键条件→检索→核对证据→回答或转人工信息”；可先用Python模块/配置，不必依赖某厂商SKILL.md加载器 |
| Tool | 检索、读取、请求补充为独立动作 | 保持工具粒度；科普问答流程放编排层，不把完整问诊塞进单个工具 |
| 确定性仲裁 | 对显式结构化claims按主题、人群、条件聚合；明确版本取代关系；未解决分歧阻断唯一结论 | 新网页尚无claims，不能发现任意自然语言矛盾。先建立少量人工核对的事实与冲突案例；引入自动检测后仍需独立评测，不能依靠模型自报可信度 |
| 回答校验 | 完整原文引用、审核门禁、来源身份与快照校验 | 当前主要为抽取式阅读；要面向患者生成易懂回答，还需事实逐条与证据对应、适用性及语义相关性检查，并验证遗漏限制条件等错误 |

## 推荐实施顺序与完成条件

1. **资料入库与审核包**：处理新5份原件，输出完整引用定位、版本与适用范围、待审清单；对小批医学审核内容建立可追溯发布机制。医学审核前仍仅预览。
2. **一次咨询的状态与追问**：定义会话、症状信息和未知值；补充回答后继续同一任务，避免重复追问；仅收集当前任务所需信息，先不建设长期健康画像。
3. **症状咨询流程**：把一般科普与个人症状咨询分开。风险相关信息优先处理；所用规则、适用人群及应对方式需要医学核对。既有代码不具有独立临床分诊能力。
4. **受控回答**：经审核的证据支持简明回答并标注出处；证据不足、适用条件缺失、冲突和失败有各自稳定出口。真实知识与演示夹具保持区分。
5. **五类场景验收**：正常问答、需要追问、证据不足、证据冲突、工具失败。将已有合成问题转成可执行用例，补人工核对的预期行为和真实语料引用；单独验证风险场景。工程通过率、检索质量及医学正确性分别报告，不能混为一个分数。

已有测试与真模型往返说明工程链路可用，不代表以上患者场景已验收。本次仅核对状态并记录计划，未改业务代码或重新执行测试。

## 多Agent何时考虑

先收集单Agent失败原因、上下文长度、调用成本及延迟。仅在可独立并行的任务、上下文隔离、权限隔离，或有评测证据支持独立校对角色时再拆分。当前优先完善单Agent；不能用多模型投票替代证据可信度或医学审核。
