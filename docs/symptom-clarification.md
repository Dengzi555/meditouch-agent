# 症状鉴别追问

宽泛的症状描述（例如只说“眼皮肿”）通过“当前回答 + 独立追问卡片”继续咨询。系统先检索可支持的一般科普信息，在回答下方只展示一个相关问题。选择后合并既有条件，重新检索并更新回答。

当前数据覆盖 10 类症状：眼皮肿、腹痛、头痛、脚踝肿、皮疹、膝关节痛、胸闷、感冒、发烧、儿童发热。其他症状继续使用原有追问和检索流程；新增症状只需扩展 JSON，不需要改代码。

## 触发条件

同时满足以下条件时，在当前回答上附加 `clarification_card`。卡片本身由注册表规划，正文沿用公开资料与本地检索流程，状态反映正文处理结果：

1. 问题命中 [症状鉴别数据](../knowledge/symptom_differentials.json) 中的症状短语（如“眼皮肿”“腹痛”“头痛”“脚踝肿”）。
2. 不是定义或科普问题（如“眼皮肿是什么原因”），也不是用户已经点名的疾病（如“麦粒肿怎么办”）。
3. 已声明的特征仍对应至少两个候选，或还有安全相关的红旗问题未回答。
4. 尚未达到六轮追问上限。

急诊、风险提醒和已有的呼吸道/腹泻科普流程优先，不会被追问卡拦截。

### 感冒与发烧的边界

`感冒` 和 `发烧` 使用 `trigger_policy: bare_only`：只有描述型输入（“感冒了”“发烧”“发烧两天了”）进入追问卡；“发烧怎么办”“感冒吃什么药”“感冒有什么症状”“发烧需要去医院吗”等行动或信息型问题继续走已有的发热/感冒流程，避免和既有验收冲突。

儿童发热的触发词更长（“孩子发烧”“宝宝发热”等），会优先匹配儿童卡片，而不是通用发烧卡片。

## 动态选项

数据文件按症状列出：

- `differentials`：候选原因及其临床特征（只在服务端使用，不展示病名）。
- `questions`：可观察的临床指征，每题有 `single` 或 `multi` 模式。
- `options`：选项只描述表现（如“伴有疼痛”“有硬结或脓点”），不描述诊断。
- `triggers`：从用户原话中识别已提供特征的短语，避免重复询问。
- `red_flag`：选择后直接给出就医提醒。

每次请求时，服务端按以下步骤生成卡片，没有针对某个症状的 `if` 分支：

1. 从原问题和已保存的条件中识别已给出的特征。
2. 用选项特征过滤候选；无法排除的候选保留。
3. 对未回答的问题计算“能把剩余候选分开多少”，按信息增益排序。
4. 综合安全相关的 `priority` 问题与特征区分度规划候选问题，每轮只展示一个问题；已答问题不再出现。
5. 若候选已经只剩一个且没有未回答的安全问题，不再追问，直接进入检索。

新增症状只需编辑 JSON，不需要改代码；启动时会校验 id、选项唯一性、特征格式和正则。

## 接口与存储

追问答案放在会话的 `clarification` 槽中，值为 JSON 字符串：

```json
{
  "v": 1,
  "symptom": "eyelid_swelling",
  "answers": {"features": ["pain", "lesion"], "course": "acute"},
  "round": 1
}
```

请求示例：

```sh
curl -s http://127.0.0.1:8765/api/agent \
  -H 'Content-Type: application/json' \
  -d '{"question":"眼皮肿","corpus":"real"}'
```

返回的 `clarification_card` 包含 `symptom`、`round`、`intro`、`notice` 和单题 `questions`。每个问题包含 `id`、`prompt`、`mode` 与 `options`（`value`、`label`，互斥项带 `exclusive`）。旧版多题数据仍可读取，前端仅呈现一题。用户可选择“暂不补充”继续自由提问。

提交答案时沿用同一会话：

```json
{
  "question": "眼皮肿",
  "corpus": "real",
  "session_id": "<上一步返回>",
  "revision": 1,
  "known_context": {"clarification": "{\"v\":1,\"symptom\":\"eyelid_swelling\",\"answers\":{\"features\":[\"pain\"]},\"round\":1}"}
}
```

`clarification_summary` 提供“伴有疼痛；3 天以内”这样的可读摘要；该摘要也会追加到检索问题中，帮助检索到对应的资料。同一症状允许只提交新增字段，服务端合并之前的答案。修订号校验仍在合并前执行。

## 安全边界

- 通用伴随症状卡的“发热”和“没有发烧”互斥，切换时保留头痛、咳嗽等其他选择。
- 服务端独立检查发热描述与体温的一致性。矛盾时返回单选确认卡，暂停一般判断；风险信号仍优先处理。
- `fever_status` 保存用户明确确认的当前状态。原始声明保留在会话存储，回答与展示使用确认后的信息；历史高体温会标记为此前记录，避免当作当前体温。新的症状或体温输入会重新触发一致性检查。
- 当前回答附带 `answer_context`，列出已知信息、本轮补充和发生变化的判断。护理、用药与就医条目分别关联来源，按已有证据展开。
- 卡片不展示候选病名，不输出“可能是某病”。
- 红旗选项（视力变化、便血、突发最剧烈头痛、小腿肿痛等）会直接返回 `risk_alert`，不继续检索。
- 选择“说不清”不会被视为正常；只表示该项未知。
- 特征表是常见鉴别要点，不是诊断标准；上线前需要医学审核。
- 达到追问上限或缺少适用证据时，说明当前判断范围与资料限制。
