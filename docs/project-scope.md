# 配置与使用范围

## 部署方式

当前采用单店本地部署，服务端绑定门店标识与 SQLite 数据库。库存路径与门店标识通过 `MED_AGENT_INVENTORY_DB`、`MED_AGENT_INVENTORY_STORE_ID` 配置。模型和视觉服务支持兼容 Chat Completions 的接口；公开知识、搜索接口由部署者维护。

启动脚本支持读取本地配置；模型设置页支持保存文本与视觉模型配置。详细字段见[配置说明](api-settings.md)。

## 药品与健康信息

库存信息来自门店录入；药盒识别负责预填，店员确认后保存。禁忌筛查基于已录入文本和顾客标签，状态包括风险命中与信息未知。药品适用性及售药判断由门店药师结合完整说明书和顾客情况处理。

健康问答按来源生成一般性解释，附引用或模型知识标记。应急功能提供通用生命支持提示、卒中警示和现场记录，具体救助遵从120调度指导。相关来源见[应急处置](emergency-support.md)。

## 功能范围

| 模块 | 当前实现 |
| --- | --- |
| 门店接待 | 五类意图路由、多轮查询补全、点选追问 |
| 商品与库存 | 商品资料、库存数量、货架、出入库流水、删除留档 |
| 用药筛查 | 已录入禁忌文本的标签匹配与未知状态管理 |
| 应急记录 | 条件式处置提示、观察记录与可复制交接摘要 |
| 身份管理 | 本地演示身份，门店数据由宿主绑定 |
| 经营系统对接 | 当前以本地库存与手工登记为主；员工权限、批号效期、收银、订单预占和结算属于后续扩展方向 |

## 数据与评测

`seed_data.py`创建独立演示库存。正式门店使用单独业务库，通过入库页面维护商品。界面截图的数据来源与复现步骤见[界面示例](interface-examples.md)。

检索报告记录题集、金标、模型配置、排名指标与耗时；工作流报告记录场景结果。各项结果按对应报告口径使用。
