# 医药科普与健康问答

默认药店工作台现在区分“解释健康问题”与“查询本店商品”。健康问题不会仅因为出现症状或药名就触发库存推荐。

| 问法 | 路径 |
| --- | --- |
| 发烧怎么办、普通感冒有哪些症状、布洛芬有什么作用 | 健康问答，默认不查库存 |
| 芬必得在哪排、本店有布洛芬吗 | 本店库存与逐药禁忌核对 |
| 发烧拿什么药，本店有吗 | 先解释健康问题，再查库存和核对风险 |
| 顾客当前呼吸困难等危险表现 | 独立风险拦截，不等待知识或库存查询 |

上述是说明示例，不是按疾病硬编码的问法表。语义理解节点结合当前问题与会话历史输出 `health_qa`、`needs_health_answer`、`needs_inventory` 和最多两组知识检索词。明确否认和未知信息继续分别保留。

检索前在同一次语义理解中生成 `standalone_query`：例如“感冒怎么办”之后的“本店有什么推荐的药”，补全为针对感冒查本店待核查商品。原问题仍保存在 `user_query`。完整问题用于本地知识检索、候选药名检索及健康回答，主题同时保存在会话中；指代不清时先澄清，不猜测旧主题。执行记录可查看实际补全的问题。

## 知识路径

1. 有相应配置时，尝试 NHS 或 ShowAPI；同时支持无需密钥的 MedlinePlus 健康主题 Web Service。
2. 外部资料未取得结果时，按原问题查询本地真实资料库。
3. 找不到适用证据或生成内容未通过引用核对时，允许明确标注“通用医学知识”的保守回答，引用列表为空。
4. 模型调用本身失败时，明确说明本轮回答未完成，不伪造知识或库存结论。

## 证据准入

`evidence_admission.py` 是程序执行的共同入口，不代表接入了真人药师或完成医学审核。公开实时结果、缓存结果和本地检索都要经过检查；健康生成入口再次检查，避免自定义加载器绕过策略。

| 资料状态 | 一般科普 | 选药证据 |
| --- | --- | --- |
| 来源可追溯、未禁止生成，但尚无本地审核记录 | 可作一般参考，标记 `general_reference`，不改审核状态 | 不作为选药依据 |
| 明确 `retrieval_only=true` 或 `generation_allowed=false` | 不进入生成模型 | 不作为选药依据 |
| 已审核且允许生成，适用范围满足 | 可作参考，仍不授权个体用药 | 可提供待核查检索词，不构成推荐放行 |
| 人群或条件不匹配、来源缺失、已撤回或快照不一致 | 拦截并记录原因 | 拦截并记录原因 |

成人、儿童、孕哺期等限制从已有资料元数据、明确的顾客信息及来源路径检查；不会扫描整篇文章，将偶然出现的“儿童”当成全文适用人群。当前未确认人群时，人群专用资料不能直接套用。该模块仍依赖正确标注和上游理解，不代替完整临床适用性判断。

被拦截公开资料不计为有效结果，可继续查询其他来源或本地资料。全部资料均不可用时，沿用明确标记的通用知识回答，不拿被拦截原文生成虚假引用；本店库存查询独立运行。选药知识兜底仍只能产生待核查检索词，不得声称通过安全核查。

准入记录含资料 ID、用途、等级和原因码，不含原文或顾客病史，写入本轮执行轨迹。没有自动“审核通过”按钮，也不修改资料的待审核状态。

公共接口只接收医学概念检索词，不发送完整聊天和顾客原文。成功结果复用既有 12 小时 SQLite 缓存；每次公开查询有请求超时与总查询预算。NHS 与 ShowAPI 仍需要供应商密钥、权限及使用条款，不能把配置开关当作已成功调用。

MedlinePlus 是健康主题资料接口，不等于完整药品说明书库。NHS 资料来自英国；处方分类、就医电话及当地服务流程不能直接套用于本地药店。

官方接口说明：[MedlinePlus Web Service](https://medlineplus.gov/about/developers/webservices/)。

## 回答与引用

健康节点按问题生成 2—5 节结构化要点，不要求每个问题填满同一模板。一般可包括判断依据、处理原则、用药注意事项、就医条件和一个关键追问。重点短语由模型提出，程序只保留正文中存在的短语。

正文使用模型真实流式响应，按完整小节增量解析。每节通过引用存在和支持性检查后立即展示，后续小节仍在生成；不是前端在完整结果上模拟打字。一般知识降级内容同步保留来源提示。最终结构校验失败时撤销增量展示，只有完整成功结果才落盘。

前端对已收到、已校验的正文做逐字平滑展开，并显示末尾光标，减少服务端分块造成的整段跳变。历史完成消息直接完整显示；库存数量、禁忌拦截等硬事实不做逐字动画。引用和追问在对应正文显示完整后出现。

证据回答要求每个要点附带真实资料 ID 与逐字摘录；程序检查摘录存在，再进行模型支持性核对。未被支持的要点不展示为有来源结论。该检查是工程护栏，不等于医学审核或正确性保证。

无来源的模型知识回答显示独立提示，不能冒充实时或经过核验的资料。两种模式都不授权售药、不生成个体化处方剂量，也不能编造本店库存或货架。商品事实仍由库存工具和程序模板提供。

## UI 与会话

沿用 `cards.snapshot`，增加 `health_answer` 卡片，包含段落、要点、重点短语、引用和可点选追问。纯健康问答不显示“禁忌数据缺失”或无关商品卡；混合问题保留医学解释和库存核查结果。

点击追问选项沿用当前会话发送补充信息。健康卡片保存到聊天数据库，刷新后恢复。历史中的助手回答只帮助理解主题和指代，不能作为顾客已报告的症状或安全批准。

主要实现：`pharmacy_semantics.py`、`health_knowledge.py`、`pharmacy_health.py`、`pharmacy_graph.py`、`web/src/HealthAnswer.tsx`。

验证：

```powershell
python -m unittest tests.test_pharmacy_health -v
python -m unittest tests.test_evidence_admission -v
npm --prefix web test
npm --prefix web run build
```

浏览器脚本 `scripts/check_health_ui.py` 对接隔离的 `scripts.pharmacy_ui_fixture`，使用合成资料与模拟模型，不作为医学效果评测。
