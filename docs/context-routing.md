# 按问题选择追问字段

2026-11-02。用户要求将固定“人群、肾功能”追问扩展为场景选择。本次修改集中在 `meditouch/patient_context.py`、前端字段显示与独立回归测试，没有重建会话存储或更改资料审核状态。

| 场景 | 必要信息 |
| --- | --- |
| 一般科普、资料区别或说明书原文查询 | 不收集个人背景，直接走资料检索 |
| 个人症状咨询 | 年龄/人群、主要症状、持续时间 |
| 涉及发热 | 在通用信息基础上问体温、测量时间、测量方式及部位；明确未测量时不反复追问测量方式 |
| 个人用药或药物合用问题 | 问药名/规格、有效成分、已经使用的药物及剂量时间、已知过敏、相关健康背景 |
| 提及基础病、孕期等背景 | 询问与本次问题相关的健康背景 |
| 补钾/钾盐/低钠盐咨询 | 保留肾功能字段；其他普通症状不固定询问肾功能 |

补充的症状文本也参与场景选择，例如原问题为咳嗽，补充称出现发热后会增加测温信息。“不清楚”“未测量”“没有说明书”保持用户声明原义，不自动变成正常值或安全结论。字段填写完成只表示可以继续资料检索，不代表足以诊断或决定用药。

前端初始仅显示通用三项；收到追问后显示本次缺失项和已填写项，隐藏无关空字段。新增字段为 `temperature_method`、`drug_name`、`drug_ingredients`；兼容原有 `population`、`renal_function`、`medications` 等字段。

当前选择规则是确定性关键词规则，覆盖本轮示例，不是通用病情理解模型、完整临床分诊或剂量工具；复杂否定、含糊表述及超出关键词的症状仍需后续案例完善。

验证命令：`.venv-agent\Scripts\python.exe -X utf8 -B -m unittest tests.test_patient_context_routing tests.test_consultation tests.test_agent_graph tests.test_agent_http -q`。测试使用隔离数据库和脚本模型，不调用付费模型、不重启主线程正在运行的服务。
